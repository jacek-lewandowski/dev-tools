# Project Architecture Map (`dev-tools`)

This document outlines the core structure, CLI scripts, and utility tools contained in the `dev-tools` repository.

---

## 📂 Core Directories & Modules

| Directory / File | Role & Responsibility |
| :--- | :--- |
| [bin/](file:///home/jlewandowski/dev/public/dev-tools/bin) | Executable bash CLI scripts, grouped by domain into `ai/`, `cassandra/` and `video/`. Two general-purpose utilities stay at the root: [collect-sha.sh](file:///home/jlewandowski/dev/public/dev-tools/bin/collect-sha.sh) (incremental sha512 manifest over a file tree) and [remove-empty-dirs](file:///home/jlewandowski/dev/public/dev-tools/bin/remove-empty-dirs) (prunes empty directories bottom-up). Each subdirectory is meant to be added to `PATH` separately. |
| [bin/ai/](file:///home/jlewandowski/dev/public/dev-tools/bin/ai) | The ai-sandbox toolchain plus [update-antigravity-ide.sh](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/update-antigravity-ide.sh), which updates the Antigravity IDE and Hub in place from the official download pages. |
| [bin/ai/create-ai-sandbox.sh](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/create-ai-sandbox.sh) | Generates and manages isolated Docker developer sandboxes per project with Rootless Docker, GUI/X11, Antigravity 2 IDE & Claude Desktop / Claude Code credential persistence, Headroom token compression, live host brain sync, a per-sandbox memory limit (`--memory=GB`, default 6, remembered in `.env`) that every start checks against the host's hand-written `AI_SANDBOX_MEMORY_BUDGET_GB` in `~/.ai-sandbox/config`, and per-sandbox SDKMAN defaults snapshotted from the host (on PATH in every shell, interactive or not, via `/etc/ai-sandbox-env.sh` and a non-interactive `sdk` wrapper), corepack-managed pnpm/yarn, a CPU cap of half the RAM in GB, rounded up, applied as a spread-out cpuset so `nproc` agrees, a build-time smoke test of the bundled tools, the host's IntelliJ IDEA mounted read-only and runnable inside, a pinned gitleaks, and the standard Claude Code plugins (list in the `CLAUDE_PLUGINS` constant) installed in the background at every container start by the entrypoint, only those absent from `claude plugin list`, so `claude plugin disable` survives restarts. Also overlay-mounts the host's Gradle and Maven caches read-only underneath, keeping sandbox writes in an ephemeral upper layer discarded at the next container start (`sandbox-doctor` inside the sandbox reports each mount). |
| [bin/ai/ai-sandbox-lib.sh](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/ai-sandbox-lib.sh) | Shared bash library, sourced by `create-ai-sandbox.sh` and every `ai-sandbox-*` command: path-derived project identity, sandbox paths, compose invocation, the shared-mount and credential-seed tables, and the image build hash. The identity formula lives here and nowhere else. Also the host memory budget (`ai_sandbox_memory_budget_gb`, read from `~/.ai-sandbox/config`) and the capacity check that sums the running sandboxes' Docker memory limits before any start, the build-cache overlay table and its check/repair/reset functions, backing the `build-caches/<key>/{upper,work}` and `build-caches/.trash/` layout under each sandbox directory. |
| [bin/ai/ai-sandbox](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/ai-sandbox) | Enter or start the current project's sandbox; runs migration first. `--print-context` reports the resolved sandbox. |
| [bin/ai/ai-sandbox-account](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/ai-sandbox-account) | `status` / `refresh` / `reset` for the AI credentials a project's sandbox uses, so each project can hold a different Claude, Codex or Gemini account. |
| [bin/ai/ai-delegate](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/ai-delegate) | Installed in the sandbox image: the lead hands one scout, writer or second-reviewer task file to Gemini through a headless `agy` run in a throwaway directory under `.ai-delegate/` and gets the answer on stdout. Exit 3 means agy is not signed in (fall back to the Claude subagent); `--conversation <id>` resumes the conversation whose id it printed on stderr. |
| [bin/ai/context-statusline](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/context-statusline) | Installed in the sandbox image and named by its managed settings as the Claude Code `statusLine` command (`refreshInterval` 10 s); on the host, the same settings entry with `bin/ai` on `PATH`. Finds `tools/` as `create-ai-sandbox.sh` does and runs `python3 -m tools.context_statusline`. |
| [bin/ai/ai-sandbox-migrate](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/ai-sandbox-migrate) | Idempotent migration of `~/.ai-sandbox` to the current layout; runs automatically before every start. Moves directories, never deletes. |
| [bin/ai/ai-sandbox-gc](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/ai-sandbox-gc) | Reclaims per-sandbox duplicates of shared assets, shared stores no sandbox mounts any more, build-cache trash leftovers a reset could not delete, and images from the old per-project naming scheme, after listing them and confirming. |
| [bin/ai/ai-sandbox-extensions](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/ai-sandbox-extensions) | Populates the shared IDE extension stores from the host, or from a throwaway container when the host has none. |
| [bin/ai/ai-sync](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/ai-sync) | Synchronizes AI shared brain, skills, curated memories, vector DB (LanceDB), Claude Code and Gemini/agy console state with Google Drive via rclone. Additive by default; `-D` mirrors with a timestamped trash. Preserves symlinks and refuses to push token-like values. |
| [bin/ai/ai-knowledge](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/ai-knowledge) | Host side of the shared knowledge repository: `init` seeds a private git remote from the knowledge seed installed beside the helper and the host's `GEMINI.md`, records the integrator in `README.md` on `main`, and on a later host shows the local `GEMINI.md` drift and offers to file it as a proposal; `sync` fast-forwards the canonical `main`, renders it into `~/.ai-sandbox/shared/knowledge` (GLOBAL.md plus per-tool role files for Claude Code, Gemini CLI, Antigravity and Codex) and syncs the project's own clone, which has `main` checked out and one local `proposal/<date>-<slug>-<hex>` branch per proposal (pushed if it changes only `proposals/`, deleted once `main` absorbed it, leased deletion on the remote by the integrator's sync); `propose` files a document as such a branch; `proposals` lists open proposal files across branches; `reports` lists open process reports, which are refs `refs/reports/<name>` outside `main` and `refs/heads/` (every clone pushes its own and drops it, only the integrator fetches them, a tombstone `refs/reports-closed/<name>` closes one); `status` without a project lists every sandbox's knowledge state; `sync --all` syncs every sandbox's clone in parallel and, for ssh remotes with a passphrase-protected key, loads the key into the user's ssh-agent or a temporary one it starts and kills. All network git happens here; no sandbox has credentials. Design: [docs/superpowers/specs/2026-09-14-shared-knowledge-design.md](file:///home/jlewandowski/dev/public/dev-tools/docs/superpowers/specs/2026-09-14-shared-knowledge-design.md). |
| [bin/ai/ai-sandbox-migrate-knowledge](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/ai-sandbox-migrate-knowledge) | Temporary, not installed: lists the running sandboxes and asks before stopping them, refuses to start when the remote is ssh and no agent holds the key, then recreates every sandbox whose knowledge stamp (`SANDBOX_KNOWLEDGE` in its `.env`) is stale or missing by re-running `create-ai-sandbox.sh` for its project. The start scripts refuse such sandboxes but never repair them; `create-ai-sandbox.sh <project>` is the single-sandbox repair. Also converts the first design's `proposals/<project-id>` branches, on the remote and in every clone on the host, into `proposal/<date>-<project-id>-<slug>-<hex>` branches, closes them into `main`, moves clones to `main` and ends with `ai-knowledge sync --all`. Delete once `ai-knowledge status` shows every sandbox as current and no clone sits on an old branch. |
| [bin/ai/knowledge-seed/](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/knowledge-seed) | Installed into `~/.ai-sandbox/bin/knowledge-seed` beside the helpers and refreshed by `ai-sandbox-migrate`. Initial content of a new knowledge repository: README, `decisions.md`, `proposals/README.md`, starter roles (planner, implementer, reviewer) and the `propose-rule` skill every sandbox gets. |
| [.agents/skills/knowledge-integrate/](file:///home/jlewandowski/dev/public/dev-tools/.agents/skills/knowledge-integrate) | The integrator's skill (this repository's sandbox is the integrator): triage proposals from every `proposal/*` branch, wait for approval, commit to `main`, close each with an ours-merge; list, read and close process reports (`refs/reports/*`, tombstone to close). Linked from `.claude/skills/`. |
| [bin/ai/ai-sandbox-stop](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/ai-sandbox-stop), [-restart](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/ai-sandbox-restart), [-attach](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/ai-sandbox-attach), [-rm](file:///home/jlewandowski/dev/public/dev-tools/bin/ai/ai-sandbox-rm) | Lifecycle and device helpers for the current project's sandbox. `ai-sandbox-rm` reports any build-cache leftover it could not delete, with the `sudo rm -rf` command to finish, and exits non-zero when one remains. |
| [bin/cassandra/](file:///home/jlewandowski/dev/public/dev-tools/bin/cassandra) | Apache Cassandra development helpers: [issue](file:///home/jlewandowski/dev/public/dev-tools/bin/cassandra/issue) opens a CASSANDRA/CNDB ticket (defaulting to the one named by the current branch), [setup-worktrees](file:///home/jlewandowski/dev/public/dev-tools/bin/cassandra/setup-worktrees) creates one worktree per release branch for a ticket, [update-my-local-release-branches](file:///home/jlewandowski/dev/public/dev-tools/bin/cassandra/update-my-local-release-branches) hard-resets the release branches to `apache/` and force-pushes them to the personal fork, [set-ci-config](file:///home/jlewandowski/dev/public/dev-tools/bin/cassandra/set-ci-config) / [_11_and_17](file:///home/jlewandowski/dev/public/dev-tools/bin/cassandra/set-ci-config_11_and_17) generate and commit a throwaway CircleCI config, [extract-cassandra-test-info](file:///home/jlewandowski/dev/public/dev-tools/bin/cassandra/extract-cassandra-test-info) summarises an ant test run, and [mount-tmpfs-for-cassandra-build](file:///home/jlewandowski/dev/public/dev-tools/bin/cassandra/mount-tmpfs-for-cassandra-build) puts the build tree in RAM. |
| [bin/video/](file:///home/jlewandowski/dev/public/dev-tools/bin/video) | ffmpeg wrappers: [recode-video](file:///home/jlewandowski/dev/public/dev-tools/bin/video/recode-video), [split-video](file:///home/jlewandowski/dev/public/dev-tools/bin/video/split-video), [video-concat](file:///home/jlewandowski/dev/public/dev-tools/bin/video/video-concat) and [video-segments](file:///home/jlewandowski/dev/public/dev-tools/bin/video/video-segments). |
| [tests/ai-sandbox/](file:///home/jlewandowski/dev/public/dev-tools/tests/ai-sandbox) | Bash test suite for the sandbox tooling, run against a temp `HOME` with a stubbed `docker`: `bash tests/ai-sandbox/run-tests.sh`. No framework required. `test-plugins.sh` runs the generated entrypoint against a stub `claude`. `test-knowledge.sh` drives `ai-knowledge` against a local bare repository as the remote. |

| [.githooks/](file:///home/jlewandowski/dev/public/dev-tools/.githooks) | Versioned git hooks, activated per clone with `git config core.hooksPath .githooks`: `pre-commit` and `pre-push` both dispatch to `gitleaks-hook`, which scans staged changes or every pushed range with the pinned gitleaks and fails closed when it is missing. |
| [tests/git-hooks/](file:///home/jlewandowski/dev/public/dev-tools/tests/git-hooks) | Test suite for the hooks against a temporary repository and bare remote: `bash tests/git-hooks/test-hooks.sh` (needs `gitleaks` on `PATH`). |

## Coupling register

The coupling register: what the tree cannot derive, the formats and files read outside this repository.
Each is marked at its definition with the searchable comment prefix
`# reads-outside:` (`grep -rn 'reads-outside:' --include='*.py' --include='*.sh' .`).

| Read outside the repository | By | Marked in |
| :--- | :--- | :--- |
| Claude Code 2.1.312 status line JSON on stdin (`session_id`, `transcript_path`, `model.display_name`, `context_window.{used_percentage, current_usage.{input_tokens, cache_creation_input_tokens, cache_read_input_tokens}}`, code.claude.com/docs/en/statusline.md) | `tools/context_statusline` | `tools/context_statusline/statusline.py`, module docstring |
| Claude Code 2.1.312 subagent transcripts, `dirname(transcript_path)/<session_id>/subagents/agent-<id>.{meta.json,jsonl}` (`description`, `finished`; `type`, `message.usage`, `subtype: compact_boundary`), undocumented beyond code.claude.com/docs/en/sub-agents.md | `tools/context_statusline` | same |
| Claude Code 2.1.x session transcripts, `<project-dir>/<session>.jsonl` and `<session>/subagents/agent-<id>.{jsonl,meta.json}` (undocumented): line `type`, `timestamp`, `isSidechain`, `isMeta`, `version`, `cwd`, `message.{id, model, usage, content}` (one line per content block, usage repeated), `attachment` of type `queued_command` with `origin.kind` `human`, `system` `turn_duration` and `compact_boundary`, top-level `cost-state` (`totalCostUSD`, `modelUsage`; the session process's total, subagents and side calls included), `tool_use` blocks `Agent`, `Bash`, `Read`, `Artifact` and tool names containing `screenshot`; meta `agentType`, `description`, `toolUseId`; a resumed session's file repeats earlier lines with the same message ids, uuids and timestamps (search: message ids occurring in more than one `*.jsonl` of the project dir) | `process-report` skill (`~/knowledge/skills/process-report`) | `~/knowledge/skills/process-report/scripts/transcript_stats.py`, module docstring (`grep -rn 'reads-outside:' ~/knowledge/skills/process-report`) |
